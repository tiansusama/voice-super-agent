# 阶段 09：能力可用性、主动恢复与重新发送（I-09）

状态：未开始。前置阶段：07、08。

[返回总计划](../V1.0.0-implementation-plan.md) · [失败处理依据](../../prd/V1.0.0.md)

## 目标

语音失败后应用继续常驻，模型可用时文字继续可用；用户可以主动恢复语音，并按输入来源再次提问或重新发送。完成 P-03 的能力与恢复验证。

## 开始前核对

- 阅读 STS 错误分类、永久错误策略和 worker 完成后的行为。
- 核对阶段 07 的设备重建、阶段 08 的输入交接、阶段 04 的实际提交与保存。
- 区分单轮请求失败、语音能力不可用、模型不可用和已取消执行对象。

## 子任务

- [ ] **09.01** 关联服务错误、当前输入、回复及能力状态。完成结果：可解释哪个能力或当前轮次失败。

- [ ] **09.02** 实现语音不可用时的文字执行装配，复用已有工作上下文。完成结果：语音错误不会使历史和界面失去访问入口。

- [ ] **09.03** 已取消 worker 清理后创建所需新执行对象。完成结果：旧回调不继续推进已失败的回复。

- [ ] **09.04** 接入“恢复语音”，读取有效配置与当前 Windows 默认设备。完成结果：恢复成功回待唤醒，失败显示具体原因。

- [ ] **09.05** 落实恢复时新旧执行对象及进行中文字回复的交接顺序。完成结果：当前工作上下文保持一个写入者，已有内容保留。

- [ ] **09.06** 失败文字消息旁提供重新发送，复制为底部新用户消息。完成结果：原消息和旧回复片段保留，新回复为文字。

- [ ] **09.07** 语音失败采用用户再问，TTS 失败保留已展示文字。完成结果：恢复成功不自动续答或重播旧回复。

- [ ] **09.08** 发布供主窗口、悬浮和托盘使用的错误/恢复事件，核对请求重试配置。完成结果：可见性规则可消费真实状态，产品不自动重复整轮请求。

## 交付物

- 能力可用性判断、执行对象重建、主动恢复和重新发送实现。
- 服务错误到界面状态的对应记录，以及 SDK 请求重试的配置说明。
- 不同能力组合下的启动与恢复验证结果。

## 验证步骤

1. 分别使 ASR、System One、模型、TTS 失败，核对原因和当前回复状态。
2. 语音失败后发送文字，核对模型可用时继续接续上下文。
3. 模型配置也缺失时，检查历史和设置仍能打开。
4. 更换有效默认设备后恢复语音，检查回待唤醒，再次唤醒交流。
5. 点击失败文字重新发送，检查追加位置、文字回复及旧记录保留。
6. 在文字回复进行中恢复语音，核对选定交接顺序；最终错误展示位置在阶段 12、13 复核。

必要测试覆盖实际错误分类、对象交接、旧回调、重发语义；再完成真实恢复演示。

## 完成条件

- [ ] 界面和历史持续可用，文字能力按模型条件运行。
- [ ] 主动恢复成功后待唤醒，上下文保留，恢复失败可理解。
- [ ] 重发追加新消息，原记录保留，语音和 TTS 失败按既定方式继续。

对应：T-10；AC-17、AC-34、AC-37、AC-38。完整可见性反馈在阶段 12～14 复核。
