# 阶段 02：桌面常驻、窗口与桥接（I-02）

状态：已完成（2026-11-07）。前置阶段：01。结果见 [阶段 02 验证记录](../../verification/stage-02.md)。

[返回总计划](../V1.0.0-implementation-plan.md) · [UI 依据](../../design/V1.0.0-ui.md)

## 目标

建立单实例、托盘常驻和前后端通信，并实机确认圆形悬浮组件所需的窗口能力。对应架构验证路径 P-01。

## 开始前核对

- 核对阶段 01 的启动结果，阅读架构的线程、桥接和 Windows 窗口约束。
- 在实施时查阅所用 pywebview 版本的官方文档与对应源码，确认 GUI 调度和窗口句柄接入位置。
- 参考选定效果图，记录当前 Windows 显示缩放与渲染器条件。

## 子任务

- [x] **02.01** 实现一个应用实例及重复启动通知。完成结果：再次启动唤出原主窗口，既有后台继续运行。

- [x] **02.02** 区分主窗口关闭、最小化、恢复和明确退出。完成结果：关闭后隐藏，托盘保留；退出才结束应用。

- [x] **02.03** 接入托盘的显示主窗口和退出操作，预留已有需求中的收音窗找回操作。完成结果：操作能到达同一桌面控制逻辑。

- [x] **02.04** 建立桥接命令入口，将调用投递到后台循环。完成结果：GUI/桥接线程不直接修改后台状态。

- [x] **02.05** 建立后台状态推送与页面就绪后的快照订阅。完成结果：页面重载或重新显示后取得当前状态，后续增量顺序正确。

- [x] **02.06** 验证窗口透明区域、圆形区域、上方问答框、按钮和滚动区域。完成结果：选定悬浮形态有实际 Windows 渲染结果。

- [x] **02.07** 验证置顶显示、不抢焦点、DPI 与任务栏避让，确定必要的 Windows 适配。完成结果：其他应用输入焦点不受自动显示影响。

- [x] **02.08** 用可控后台活动持续发送事件，检查隐藏、显示和退出仍及时生效。完成结果：事件推送不阻塞 GUI 或后台控制命令。

## 交付物

- 桌面生命周期与单实例实现、桥接的首版命令和事件接口。
- 主窗口及可复用悬浮宿主，Windows 实机截图与操作结果。
- 渲染器和必要原生适配的选择记录，说明尚需在真实语音中验证的部分。

## 验证步骤

1. 启动两次，核对只有一个 Agent 宿主，并由原窗口响应。
2. 依次关闭、托盘显示、最小化、恢复、明确退出，观察后台生命周期。
3. 在其他软件输入时自动显示悬浮宿主，检查键盘焦点、可点击区域与滚动。
4. 在实际 Windows 缩放下核对圆球外区域、框间间距、悬停按钮和任务栏位置。
5. 持续推送后台事件并操作窗口，最后退出并检查资源结束。

窗口和焦点通过实机验证；桥接只对顺序或线程问题编写必要测试。
