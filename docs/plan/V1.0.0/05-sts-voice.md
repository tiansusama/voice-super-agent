# 阶段 05：耳机下的 STS 连续语音链路（I-05）

状态：未开始。前置阶段：04。

[返回总计划](../V1.0.0-implementation-plan.md) · [STS 流程依据](../../design/V1.0.0-architecture.md)

## 目标

在本项目内复用 STS 的语音主流程，先在耳机环境完成连续交流、附和和接管，明确原生事件与 UI、持久化的衔接。

## 开始前核对

- 阅读 STS 入口、火山适配和 System One 对应实现及测试，核对选定 Pipecat 版本中的聚合、轮次和取消行为。
- 确认 ASR、DeepSeek、TTS、System One 的本地配置条件和默认音频设备。
- 已知节点顺序为输入 → ASR → System One → 用户聚合器 → DeepSeek → TTS → 输出 → 助手聚合器。

## 子任务

- [ ] **05.01** 迁入所需火山适配、System One 和高价值测试，保留来源说明。完成结果：本项目导入路径独立于 STS 目录。

- [ ] **05.02** 装配本地采集与播放，核对 16 kHz 输入、24 kHz TTS 与设备格式衔接。完成结果：耳机环境采集和播放通路可用。

- [ ] **05.03** 保留 Silero VAD、转写判起、Smart Turn、共享上下文及原生聚合顺序。完成结果：ASR 分句定稿没有被直接当成用户轮次结束。

- [ ] **05.04** 通过开发验证入口激活语音，完成识别、模型生成、合成、播放。完成结果：用户发言获得语音和 UI 文字回复。

- [ ] **05.05** 接入 System One 的候选修订、附和和确认接管结果。完成结果：附和继续播报，接管交给原生打断。

- [ ] **05.06** 接入尚未播报时新语音直接进入用户轮次的原生通路。完成结果：生成期间开口按已有机制处理。

- [ ] **05.07** 订阅识别、用户轮次、助手提交、附和与播放事件。完成结果：UI 和持久化使用相应事实更新。

- [ ] **05.08** 扩展阶段 04 的保存，分别表达展示文本、模型提交和真实状态。完成结果：被打断片段正常展示，附和保存在展示历史并按 STS 从模型上下文过滤。

## 交付物

- 迁入并适配的语音实现、独立语音装配和本地音频基础接入。
- 原生事件到消息、状态与保存逻辑的对应记录。
- 耳机下正常对话、附和、接管和转写修订结果。

## 验证步骤

1. 进行连续问答、补充和纠正，检查回答接续与语音/文字输出。
2. 用包含多处分句的表达检查用户轮次处理。
3. 播报中分别附和和提出新问题，观察分类、打断、片段保存和后续回答。
4. 覆盖候选转写修订和分类结果迟到，核对对应关系。
5. 在尚未播报的生成阶段开口，确认走原生直接通路。

运行迁入的相关测试，并对事件提交顺序做必要集成验证；真实耳机演示用于验证完整服务连接。

## 完成条件

- [ ] 耳机下真实语音链路可连续使用。
- [ ] 轮次、附和和接管行为沿用 STS，可定位对应原生事件。
- [ ] 对话和附和能保存，被打断回复保留普通文字展示。

对应：T-06、T-08；AC-04～AC-08、AC-28 的生成阶段。外放在阶段 07，最终悬浮表现由阶段 13 完成。
