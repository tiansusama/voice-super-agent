## 实现与自动验证记录（2026-11-09）

`voice/volcengine.py` 和 `voice/interruption.py` 分别迁自 STS 根目录的 `local_volcengine_services.py`、`system_one_interruption.py`，文件中保留来源说明。底层继续使用已锁定的 Pipecat `de8998789`，运行时导入本仓库代码。

`Conversation` 同时支持文字和语音装配。语音使用输入 → 火山 ASR → System One → 用户聚合器 → DeepSeek → 火山 TTS → 输出 → 助手聚合器，保留 Silero VAD、转写判起及默认 Smart Turn。`voice/pipeline.py` 持有本地音频和 HTTP 会话，停止 worker 后释放 WebSocket、HTTP 和 PortAudio 资源。

通过 `--desktop-check` 中的“开始语音联调”和“停止语音联调”控制语音。切换时先关闭旧执行对象，等待已有上下文保存，再使用相同的原生模型记录创建新执行对象。本轮语音联调期间暂停文字发送，停止语音后可继续文字追问；未完成语音与文字的交错接管仍由阶段 08 完成。

| 原生事实 | 展示与保存 |
| --- | --- |
| System One 放行的转写 | 更新当前语音输入片段；ASR 分句定稿继续交给原生用户轮次 |
| 非推测 `LLMContextUserTurnFrame` | 将实际提交的用户正文标为完成，并关联后续回复 |
| 空轮次恢复的 `LLMContextFrame` | 保留原识别片段的未完成状态；内部提示仅存入原生模型记录 |
| `LLMTextFrame` | 更新 UI 展示原文，独立于语音播放进度 |
| 播放路径末端助手聚合器处理结束、打断或取消帧 | 保存原生实际提交内容和回复状态，展示片段按已有内容保留 |
| `UserBackchannelFrame` | 保存 `source=voice`、`status=backchannel` 的用户展示消息，关联正在回复的消息，模型上下文继续由原生机制过滤 |
| `BotStartedSpeakingFrame` / `BotStoppedSpeakingFrame` | 更新实际播放状态 |

现有数据库字段可表达上述内容，沿用原有初始化脚本；附和记录不替换原用户输入与回复的关联。保存失败时停止活动语音；准备语音期间已有保存失败则终止本次启动。

自动测试使用本地 WebSocket、SSE、HTTP 音频服务及可控内存音频输出，执行实际迁入适配器、System One 与原生聚合器；集成测试以确定的静音超时推进轮次，生产配置继续采用 Smart Turn。覆盖转写修订及去重、附和过滤、播报接管、生成阶段开口、显示与播放提交差异、语音与文字接续、未完成回复和附和重启恢复、设备启动失败、保存失败停语音，以及空轮次内部提示的隔离。
