# 阶段 08：文字与未完成语音的接管协调（I-08）

状态：未开始。前置阶段：05；可在阶段 06、07 收尾前开始。

[返回总计划](../V1.0.0-implementation-plan.md) · [输入接管依据](../../design/V1.0.0-architecture.md)

## 目标

语音和文字接续同一上下文；发送文字替代未完成语音，旧转写即使迟到也不再触发回答，之后的新发言正常处理。对应 P-03 的输入验证。

## 开始前核对

- 核对 RTVI 的打断、flush、输出选择和追加文字顺序。
- 阅读 ASR 接收任务、System One 候选、用户聚合器和轮次控制器，区分聚合、队列和云端在途位置。
- 确认 `UserTurnResponseCancelFrame` 的实际职责；它不能直接被视作清除全部旧语音的入口。

## 子任务

- [ ] **08.01** 建立文字到达前后音频与识别结果所属输入的表示。完成结果：结果归属依据采集和连接关系，避免仅按收到时间判断。

- [ ] **08.02** 构造聚合未结束、队列内转写、云端结果迟到三类可控场景。完成结果：能观察旧输入当前所在位置和原生提交状态。

- [ ] **08.03** 比较局部输入重建与聚合器适配，选定最小可用实现。完成结果：记录对原生流程的接入位置、改动范围和延迟结果。

- [ ] **08.04** 文字接管时阻止旧输入继续进入聚合，按原生顺序打断并提交旧回复。完成结果：已提交历史保留，旧轮次不再随后发起推理。

- [ ] **08.05** 清理受影响的候选、轮次判断与语音聚合；需要更换对象时受控交接。完成结果：新旧对象不会并发写入同一工作上下文。

- [ ] **08.06** 追加文字并选择文字输出，处理完成后继续原有语音激活状态。完成结果：待唤醒发文字仍待唤醒，激活时发文字保持激活。

- [ ] **08.07** 恢复接收新发言，必要短时音频仅在内存处理。完成结果：新语音能正常进入原生轮次，旧输入尾段不被重复处理。

- [ ] **08.08** 覆盖连续文字、重新发送入口可复用的发送逻辑和不同处理阶段。完成结果：输入来源、回复形式与上下文顺序一致。

## 交付物

- 输入归属、取消与对象交接实现，统一的文字接管路径。
- 三类迟到情形的测试及真实语音/文字切换结果。
- 所选实现和源码接入点记录；这部分属于本项目新增适配。

## 验证步骤

1. 语音已经出现分句但尚未说完，发送更正文字，检查只回答文字。
2. 让旧 ASR 结果在文字之后返回，检查不会再次触发旧回复。
3. 接着发起新的语音，检查它可正常回答并接续上下文。
4. 播报、尚未播报的生成及连续文字场景分别接管，核对提交顺序。
5. 阶段 06、10、09 接入后，分别复核语音激活状态、工具中接管和重新发送。

核心测试控制 ASR 返回顺序与队列状态，并以真实模型和音频做集成验证。

## 完成条件

- [ ] 三种位置的旧输入都不会在文字接管后产生旧回答。
- [ ] 新发言与连续文字可正常处理，已提交历史保留。
- [ ] 语音与文字共享上下文，回复形式跟随输入来源。

对应：T-05、T-08；AC-09、AC-10、AC-20、AC-33，AC-28 的跨输入部分。
