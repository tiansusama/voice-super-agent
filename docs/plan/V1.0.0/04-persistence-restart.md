# 阶段 04：对话保存与重启恢复（I-04）

状态：已完成（2026-11-09）。前置阶段：03。结果见 [阶段 04 验证记录](../../verification/stage-04.md)。

初始化脚本版本由用户确认为 `V1.0.0_001`，保存失败暂停新消息，退出保存失败保留窗口。

[返回总计划](../V1.0.0-implementation-plan.md) · [PRD 依据](../../prd/V1.0.0.md)

## 目标

把当前展示与模型实际上下文保存到 SQLite，正常退出后恢复同一 Agent 的交流内容，建立后续历史回读的数据基础。

## 开始前核对

- 读取阶段 03 的消息、提交与退出路径，确认有哪些真实事件可用于保存。
- 区分展示片段、原生提交内容、消息状态和当前展示范围。
- 按用户数据库规范，编写初始化脚本前确认版本编号，再新建脚本文件。

## 子任务

- [x] **04.01** 设计消息、来源、时间、回复关联、模型消息和当前工作窗口的保存表示。完成结果：字段能表达真实提交与展示差异。

- [x] **04.02** 版本确认后编写初始化脚本，落实数据库打开和关闭。完成结果：新环境可以初始化数据库。

- [x] **04.03** 定义用户提交、助手完成/打断、流式片段与退出的保存时机。完成结果：已保存内容有明确来源，流式写入可合并。

- [x] **04.04** 把关联数据放在一致事务内更新，保存实际模型提交顺序。完成结果：重启不出现失去关联的消息或错误顺序。

- [x] **04.05** 将数据库工作放到受控 I/O 执行位置。完成结果：较长读写不阻塞后台对话控制。

- [x] **04.06** 正常退出时停止当前处理、保存已有内容并释放资源。完成结果：已有片段和未完成状态可恢复。

- [x] **04.07** 启动加载展示范围和模型上下文，已有未完成回复等待用户继续。完成结果：重启后不自动续写或重播。

- [x] **04.08** 保存失败反馈到应用状态，给出原因。完成结果：未保存内容不会被宣称已恢复。

## 交付物

- 经确认版本的新建数据库脚本、SQLite 保存与加载实现。
- 消息和工作窗口的数据说明、提交及正常退出的保存时序。
- 保存、失败和重启恢复测试记录。

## 验证步骤

1. 完成数轮文字对话，正常退出并重新启动，核对消息原文与追问接续。
2. 在回复生成期间退出，核对重启保留片段和真实状态。
3. 构造展示文字与模型提交不同的情况，分别检查恢复结果。
4. 模拟一次保存失败，检查原因和当前状态反馈。
5. 检查持久化内容，确认默认保存文本与必要状态。

核心测试覆盖事务关联、提交顺序、两种文本口径及正常退出恢复；数据规模加载在阶段 10、14 继续验证。

- [x] 未完成回复保留状态，由用户继续输入。
- [x] 保存失败可见，数据库资源和后台退出顺序明确。
