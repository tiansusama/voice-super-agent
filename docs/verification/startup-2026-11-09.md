# 桌面启动故障与语音响应时间记录

日期：2026-11-09。环境：当前 Windows 开发机，项目 uv 环境与已有服务配置。

## 已修复并验证

1. 本地唤醒模型已通过项目脚本下载、解包并由实际桌面进程加载。
2. `WakeAudioGate` 创建静音帧时使用 `dataclasses.replace()`，导致 Pipecat 帧的元数据重新初始化，ASR 读取 `voice_epoch` 失败。改为更新原帧音频负载，保留输入归属与准入信息。原生流水线回归测试在修复前稳定失败，修复后通过。
3. 录放音回调把非零 `status_flags` 当作永久设备错误，返回 `paAbort`。已按 PortAudio 的缓冲状态定义继续处理当前音频块；实际处理异常继续上报，现有端点与流存活检查继续处理设备失效。测试覆盖录音溢出/欠载及播放欠载/溢出/预填充，同时验证音频交付、播放参考和真实异常路径。

状态码 `2` 是 `paInputOverflow`，`4` 是 `paOutputUnderflow`，均属于回调缓冲状态。依据：[PortAudio 状态定义](https://files.portaudio.com/docs/v19-doxydocs/portaudio_8h.html)、[PyAudio 回调接口](https://people.csail.mit.edu/hubert/pyaudio/docs/)。

当前机器的 DeepSeek SDK 经过 `127.0.0.1:7890` 代理时连接失败，进程设置 `NO_PROXY` 包含 `api.deepseek.com` 后，SDK 模型列表查询及应用实际对话请求成功，实际对话返回 HTTP 200。此次仅调整启动进程的环境。

在继承相同代理配置的 PowerShell 中重新启动，可使用：

```powershell
$env:NO_PROXY = $env:NO_PROXY + ',api.deepseek.com'
uv run --locked voice-super-agent
```
