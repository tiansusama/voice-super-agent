# V1.0.1 桌面对接验收

## 已验证

| 场景 | 验证方式 |
| --- | --- |
| 当前用户输入创建任务，首次重发才创建任务时跨重启去重 | 本地模型接口替身、真实主对话、Worker、SQLite、MCP 文件工具和 DesktopApi |
| 正式启动后派工并正常退出 | 普通应用入口、真实 WebView2、临时数据库和目录、本地模型接口替身 |
| 执行结果重启后再次显示，通知不重复，已读状态保留 | 临时 SQLite 先保存任务及结果，重启 Runtime 后核对聊天 |
| 内置工具发现、文件路径范围、同名保护、MCP 取消后的实际结果 | MCP 内存会话、临时目录、受控窗口动作 |
| 主窗口显示、隐藏、可见性回读 | Windows 原生 WinForms 与已加载页面的 WebView2 |
| 任务详情答复、并发上限修改并刷新状态 | 浏览器、模拟桌面桥接 |
| 等待任务动作完成后退出，可中途撤回 | Runtime、DesktopApi、TaskRuntime、MCP 和可控窗口动作 |
| 语音派工、任务播报等待、待答问题优先、接管和待唤醒保留未读 | 现有 STS 流水线、模拟 ASR/TTS、可控音频输出和任务服务 |

回归命令在仓库根目录执行。

```powershell
uv run --locked pytest -q
npm --prefix frontend run build
npm --prefix frontend test
```

## 现场联调

1. 在临时目录放置 UTF-8 源文件，用文字明示源文件和新建输出文件的绝对路径。检查主对话卡片、详情中的执行记录及实际产物。对同名输出复测，确认源文件和已有产物仍可读取。
2. 让两个独立任务运行，在设置中调低并发上限。检查在途任务和排队任务，再对照任务详情验证暂停、继续、取消和重试。需要澄清的任务保留问题，答复关联到该任务。
3. 在动作执行期间请求退出并撤回，再次请求退出并重启。检查原运行记录、已保存结果、待核对步骤和未读通知。目的路径已有文件时，核对界面中的证据并由用户确认归属。
4. 用真实麦克风发起语音任务，分别测试播报中附和、接管和回到待唤醒。观察实际发言结束、首音频、停止播报和任务命令响应的时间，记录耳机或扬声器类型、设备条件和测量点。

验收编号和分工见 [施工计划](../plan/V1.0.1-implementation-plan.md#5-合并及联调顺序)。
