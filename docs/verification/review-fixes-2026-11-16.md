# 项目审查问题修复记录

日期：2026-11-16。分支：`feature/review-fixes`，从 `2cc596e` 创建。按用户要求，三个问题分别修复、验证和提交。本轮使用假设备、内存音频和本地协议服务，真实收音、播放及云服务未参与测试。

## 音频打开取消与关闭并发

提交：`879606a`，修复音频设备打开取消时与资源关闭的竞态。

`DesktopAudioTransport.open()` 将阻塞的设备打开工作保留在独立任务中，通过 shield 等待其完成；收到取消时继续持有设备锁，线程结束后再传播取消或打开异常。随后执行的关闭操作能够回收已创建的全部流，重复取消也保持这个顺序。

新增 4 个回归场景，覆盖打开成功/失败与单次/重复取消。音频测试共 18 项通过。

## 语音切换清理失败后的错误反馈

提交：`2ab4663`，修复语音切换清理失败后状态卡住的问题。

`Runtime._set_voice()` 在唤醒或结束失败后，记录原始错误；清理再次失败时追加清理原因，并仍将状态更新为语音不可用，清除当前回复关联。旧对象继续保留到后续清理，用户可以恢复语音、继续文字或退出。

新增 6 个回归场景，覆盖唤醒/结束语音发生持续 flush 超时后，分别恢复语音、发送文字和退出。语音与恢复相关测试共 60 项通过。

## System One 判意上下文预算

`SystemOneInterruptionProcessor` 对实际发送的 `conversation` 应用已有工作窗口投影，使用 64 KiB 紧凑 UTF-8 字节预算、0 工具预留和完整近期轮次。工具调用与结果一起保留；原生上下文和数据库记录继续保存完整原文。

按用户确认的取舍，最新完整轮次本身超限时反馈明确错误，沿现有判意失败和恢复流程处理。`questions` 继续承担原有判意指令，`user_transcript` 保留原文；工作窗口内部的空系统位会在构造 `conversation` 后移除。

新增 5 个回归场景：普通/含工具历史增长后请求有界、原文保持完整；最新用户消息、助手消息或工具结果超限时停止发出请求并反馈错误。原有空上下文、转写修订、附和和接管场景继续由现有测试覆盖。
