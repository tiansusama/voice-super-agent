## 已确认的预算与模型限制

本次使用项目 `.env` 中的 `deepseek-flash`、官方 `/v1` 地址。官方 `GET /models` 返回上下文 `1,048,576` tokens、最大输出 `393,216` tokens；这与[模型说明](https://api-docs.deepseek.com/quick_start/pricing/)相符。模型输入加输出受到上下文限制，详见[请求参数](https://api-docs.deepseek.com/api/create-chat-completion/)。

用户已确认以下应用默认值：

| 项目 | 默认值与计量 |
| --- | --- |
| 输入内容总上限 | `64 * 1024 = 65536` 字节，`messages` 与 `tools` 分别按紧凑 JSON、`ensure_ascii=False` 编码为 UTF-8 后计量 |
| 工具结果余量 | 32768 字节；普通请求预留，工具循环按当前轮实际工具结果字节数使用，上限仍为 65536 |
| 原文预览 | 最多 8 条，预览消息的序列化内容合计最多 4096 字节 |
| 单条预览 | 展示原文前 120 个字符，附稳定消息 ID、回复 ID、时间、角色、来源和状态 |
| 输出 | 每次实际请求设置 `max_tokens=8192` |

字节预算用于限制本应用装载内容。它不是 tokenizer 的精确 token 计数；[官方 token 说明](https://api-docs.deepseek.com/quick_start/token_usage/)明确不同模型的换算不同，实际用量以返回的 usage 为准。当前所选预算明显小于本次核实的 1M 上下文，运行时直接沿已配置服务发送请求，启动不依赖额外模型元数据查询。

设 `B=65536`、`R=32768`、当前轮原生工具结果的序列化字节数为 `T`，本次装载目标为：

`B - R + min(T, R)`

其中同时计入系统指令、当前问题、工具定义与近期消息，并为有限预览留出空间。最后对实际投影后的 `messages`、`tools` 再按同一方式计量。工具定义和带时区的当前时间提示均进入预算；序列化包括 JSON 标点、转义、中文与 emoji 的 UTF-8 字节。

## 请求投影、轮次与稳定引用

`WorkingContext` 在实际模型请求构造处整理输入，普通文字、语音、打断后的请求及工具结果循环共用这一入口。原生聚合器继续维护完整提交，SQLite 继续保存所有原文、模型消息、工具调用与结果；请求中的投影不反写原生上下文。

- 从当前工作范围选取最近的完整用户轮次，保留当前问题，较早轮次按预算整体移出。
- 移出内容按时间顺序中的最近记录提供有限原文预览和稳定引用；正文由 `history_read` 展开。语音附和、被打断和未完成内容按已有展示属性回读。
- 原生工具批次以实际 `FunctionCallsStartedFrame` 中的调用 ID 记录。原生聚合器可能将同批调用分别保存成多条助手/工具消息，投影仍将它们作为同一批处理。
- 当前工具循环超预算时，较早完成的批次连同调用和结果整体移出请求，保留当前问题、最新完整批次及回读提示。最新并行批次本身超预算时明确失败，完整结果继续保存，后续短输入正常处理。
- 完整展示和原生历史仍保存在运行时内存及数据库；本次有限窗口限定实际送入模型的内容。历史页面按需装载继续在对应界面计划中落实。

工具批次信息用于当前执行对象的请求整理；正常重启等待用户新输入，旧轮次整体处理，旧原文及引用仍有效。没有增加数据库迁移或修改原脚本，当前数据库仍为 `user_version=2`。

## 重新开始与关闭顺序

用户确认重新开始后回到待唤醒。主窗口 `restart_conversation` 命令执行：

1. 标记 `restarting`，暂停新输入，取消等待模型启动的输入消费者和未完成的语音准备任务。
2. 取得执行锁；暂停旧语音边界，发送原生打断，等待工具取消和实际上下文提交，再关闭旧 worker。助手片段保留为 `interrupted`，未提交语音保留已有展示与未完成状态。
3. 完成旧记录保存，再用已有保存事务提交展示与模型起点。事务成功后更新内存范围并清空当前展示；失败保留旧范围并反馈原因。
4. 清除旧读取状态，原先可用的语音宿主重新准备为待唤醒。历史工具继续可用，输入框未发送草稿保留。

两处起点分别为 `display_start_position`、`model_start_position`。下次请求从新范围开始，不带重新开始前的正文、预览或引用；旧数据始终可通过只读工具重新定位。

退出与重新开始共用执行锁。退出先停止输入与准备任务，再在锁内清理最新的热键、空闲和设备观察任务，等待当前范围更新后保存。这样退出不会把旧起点覆盖回数据库，也会清理重新开始期间新建的观察任务。

关闭等待在原生排空与 runner 结束之间协调：worker 已结束时采集其最终上下文；真实排空失败时仍释放资源并明确反馈。退出失败会恢复 `exiting=False`、显示 `exit_error`，允许再次退出重试。

## 自动化、真实模型与性能证据

`tests/test_context_window.py` 新增 20 项验证，覆盖：

- 近期完整轮次、Unicode 字节计量、工具定义预算、有限预览与稳定引用。
- 文字及模拟语音连续读取长原文，每次请求有界、调用与结果成对，完整读取结果仍保存在原生记录。
- 原生同批三个独立助手/工具记录超预算时整体拒绝，完整结果保存，后续短输入可继续。
- 当前问题超预算的明确反馈；重新开始中的输入拒绝和旧读取取消。
- 流式片段保存、未完成语音与迟到旧帧隔离、旧 ID 回读、重启后的新工作范围。
- 窗口事务失败保留旧范围；退出与窗口保存、语音重建并发时保持数据库一致，清理所有观察任务。
- worker 正在结束时快速关闭，以及语音准备清理失败后的资源释放与退出重试。

真实模型使用独立临时数据库，种入 40 轮、80 条历史及原生记录；目标记录位于最早一轮，未装入第一个请求。使用项目当前配置，三项验证均完成：
