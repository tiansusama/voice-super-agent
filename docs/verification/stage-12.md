## 界面与运行时接入

`frontend/src/MainWindow.tsx` 承载主界面；`main.tsx` 继续负责桥接订阅、序号衔接和悬浮宿主。主界面使用后台快照中的消息 ID、角色、来源、状态及能力信息，操作调用已有 `command`、`send_text`、`resend_text`。

- 左侧为对话与历史入口，设置位于侧栏底部；顶部显示名称、语音状态与处理状态，底部固定输入区。
- 用户头像和“我”在右侧独占一行，浅杏色气泡位于其下方；助手图标和“小博”在左侧，正文对齐姓名位置。
- 识别、判意、思考、读取历史、播报和保存异常来自真实状态；准备或交互时提供“结束语音”。语音失败展示原因及“恢复语音”；退出保存失败提供“再次退出”。
- 流式回复按原消息 ID 更新，附和及旧回复片段正常显示。失败文字的原用户消息旁显示“重新发送”，通过原消息 ID 追加新输入，旧记录保留。
- 输入保留 Enter 发送、Shift + Enter 换行和中文输入法回车规则；多行输入按内容增加高度，最高 132 CSS px。向上阅读暂停跟随，点击“回到最新”恢复。
- 导航切换保留聊天节点与草稿；窗口隐藏、最小化或恢复继续使用相同订阅与快照序号。

用户已确认本轮历史和设置的范围：历史页说明如何按主题、关键词和时间回忆旧内容；设置页展示当前生效的唤醒词、组合键、超时及模型/设备信息。完整浏览、分页及编辑继续由[阶段 14](../plan/V1.0.0/14-settings-history-ui.md)实现。服务参数继续通过本地 `.env` 配置并重启生效。

## 页面自动化

使用 Playwright CLI 在真实 Chromium 中运行，桥接快照与命令返回使用内存样例；本项验证页面事件和呈现，后台行为由已有核心测试与下方原生检查覆盖。

主检查 25 项通过：身份行位置、导航与草稿保留、输入法回车、换行与发送、流式消息、附和与回复片段、结束语音、失败文字重发、恢复、保存/退出失败、重新开始、长消息滚动、回到最新、窗口状态快照、旧序号排除及窄窗口布局。补充检查 4 项通过：失败与恢复截图包含重发入口、历史读取期间可输入、播报时文字接管保留片段、准备阶段可结束语音。

最终生产构建补查 4 项状态优先级：语音激活时的文字回复显示“正在回复”，等待用户时显示“正在聆听”，实际播放显示“正在播报”，读取历史时优先显示“正在读取历史”。文字回复和收音事件独立更新，顶部处理状态按实际活动选择。

视口覆盖 960 × 640、640 × 440、512 × 352 CSS px；窄视口输入与发送可见，页面无横向溢出。512 宽用于检查较大缩放造成的空间收缩；实际 Windows 缩放结果如下。

## Windows 原生窗口

使用实际 pywebview / EdgeChromium、Python Runtime、Pipecat 文字流水线和本地 SSE 模拟模型服务。验证使用独立数据库 `.local/verification/stage-12/native.sqlite3`，模型配置仅注入检查子进程；本次未启动麦克风或播放设备。

8 项原生检查通过：

1. 生产构建在 EdgeChromium 正常渲染。
2. 输入经真实 pywebview 桥接进入 Python，并从本地服务收到流式回复。
3. 隐藏主窗口后后台计数和回复生成继续。
4. 找回窗口后显示隐藏期间完成的回复，未发送草稿保留。
5. 最小化并恢复后消息数量保持一致。
6. 最小窗口无横向溢出。
7. 最小窗口的输入区保持可见。
8. 点击真实“重新开始”命令清空当前展示并保留草稿。

实际环境为 Windows 11、192 DPI / 200% 缩放、`devicePixelRatio=2`。常规窗口 960 × 680，页面视口 947 × 645 CSS px；最小窗口 640 × 480，页面视口 627 × 445 CSS px。系统边框与原生标题栏占用其余空间。

原生截图为 `native-generating.png`、`native-restored.png`、`native-compact.png`、`native-restarted.png`，结果记录为 `native-result.json`，均位于上述本机产物目录。
