## 接口与返回边界

两个工具读取本项目数据库的 `display_messages`，保留实际展示原文；模型消息与工具调用、结果继续由原生聚合器维护。工具不提供文件、网络或其他应用的数据入口。

`history_search` 参数：

| 参数 | 含义与边界 |
| --- | --- |
| `keywords` | 最多 8 个关键词，每词 1～100 个字符；任一关键词命中。主题由模型拆为可能出现在原文中的词，并可改写后重查 |
| `start_time` / `end_time` | 带时区的 ISO 8601 时间，起点包含、终点排除；统一按 UTC 比较 |
| `limit` | 默认 5 条，最多 20 条 |
| `before_position` | 首次省略；续页使用 `next_before_position` 并保留原查询条件，按保存位置从新到旧读取 |

查询前等待近期保存完成，排除正在提问的当前回复，覆盖当前工作范围之外的全部已保存历史。关键词使用 `instr(lower(text), lower(?))`，两字中文词直接按原文子串查询，`%`、`_` 按字面匹配。中文主题定位采用关键词检索，首版没有引入向量或全文检索。

返回包含 `status`、`matches`、`next_before_position`；每个命中包含稳定的 `id`、保存位置 `position`、`reply_id`、角色、来源、状态、UTC 时间、错误原因、正文前 160 字符预览和全文字符数。预览用于定位，回答细节前读取原文。位置游标保证后续追加记录不会挤动已开始的向前分页。

`history_read` 参数：

| 参数 | 含义与边界 |
| --- | --- |
| `message_id` | 检索或关联列表返回的稳定消息 ID |
| `offset` | 从 0 开始的 Unicode 字符偏移，默认 0 |
| `limit` | 默认 2000 个字符，最多 8000 个字符 |
| `related_offset` | 同轮关联列表偏移，默认 0；每次最多 10 条 |

返回 `message.text` 原文片段、元数据、`total_characters`、本次 `offset`、`next_offset`。`next_offset=null` 表示该正文读完，中文、换行和 emoji 均按字符衔接。`related` 按保存顺序列出同一 `reply_id` 的消息引用、角色、来源、状态、时间及字符数，使用 `next_related_offset` 续页。`previous_message_id`、`next_message_id` 指向相邻展示记录，可继续调用读取。

被打断、未完成、失败与附和消息保留自身属性。全文与同轮关联各自有界，长对话不会一次返回全部正文。偏移等于正文长度返回空的末段；超出正文长度返回参数错误。

## 原生工具循环、状态与取消

- 普通文字与语音都注册 `history_search`、`history_read`。文字接管后继续保留这两个工具；`end_voice` 只向语音轮次提供。
- 工具通过 `FunctionSchema.handler` 注册，沿用 Pipecat 默认的 `cancel_on_interruption=True`。实际工具开始和结束产生 `history` 事件；主窗口与当前语音卡片据此显示读取中、找到、未找到、线索不足、参数无效、失败或取消。
- 查询与 SQLite 保存共用已有串行 I/O 线程。新输入取消等待中的查询后，已进入 SQLite 的只读操作可完成；原生工具任务已取消，迟到数据不会继续调用结果回调或发起旧回复。查询前的保存等待使用 `shield`，保存事务继续完成。
- 原生助手聚合器提交结果或 `CANCELLED` 后立即采集上下文并请求保存。已完成的同组结果继续保留，取消的调用保留调用 ID 和取消结果；新输入决定后续是否重新检索。
- 语音原生工具活动期间暂停空闲计时；尚未播报时，用户新语音直接进入轮次。已开始播报后的接管继续沿用现有判意机制。
- `not_found`、`needs_clarification`、`invalid_arguments`、`failed` 都作为真实工具结果提交给模型。数据库异常携带实际原因，界面显示历史读取错误；模型仍可继续处理后续输入。
- 每次模型请求都提供当前本地时间，常驻进程跨午夜后继续按新日期解释时间线索；时间提示只进入请求，不累积进原生历史。

本项目锁定的 Pipecat 版本在 OpenAI 兼容流中每块只处理 `tool_calls[0]`，同块多工具及交错参数会遗漏调用。自有 `TextDeepSeekService.get_chat_completions` 按 `index` 聚合各调用片段，再逐调用交给原生解析器；正文和 usage 持续传递，结束或取消时关闭 SDK 流。执行、分组、结果提交与取消仍由原生工具机制负责。[DeepSeek 流式结构](https://api-docs.deepseek.com/api/create-chat-completion/) 定义了 `tool_calls` 数组及后续参数片段；注册和取消依据 [Pipecat Function Calling](https://docs.pipecat.ai/pipecat/learn/function-calling)。

## 数据库迁移与规模测量

用户已确认新迁移版本 `V1.0.0_002__index_history_reply.sql`。它在一个事务内添加 `(reply_id, position)` 索引并设置 `user_version=2`；首次初始化依次执行 001、002，已有版本 1 数据库只执行 002，原初始化脚本保留。旧库升级测试核对展示原文、原生上下文与工作窗口均可恢复。

在临时数据库保存 50,000 条记录，每条约 1000 个中文字符，总数据库约 198 MB；短词命中约每 1000 条出现一次，每页 5 条。测试在本机运行 3 次查询，结果如下：

| 操作 | 实测耗时 |
| --- | --- |
| 两字中文“杭州”命中 | 37.38 / 38.80 / 39.01 ms |
| 不存在关键词，全表扫描 | 315.11 / 315.49 / 312.87 ms |
| 有命中的时间范围首页 | 0.63 / 0.34 / 0.31 ms |
| 按 ID 读取原文及同轮关联，新增索引后 | 0.62 ms |
| 同轮关联未建索引时 | 142.59 ms |
| 查询期间每 10 ms 的后台计时任务最大间隔 | 22.50 ms |

耗时含执行线程往返；它们是本次环境的测量值。未命中子串查询仍需扫描历史，但发生在 I/O 线程，后台事件循环继续处理交互。按测量结果仅增加同轮关联索引。

## 验证结果

`tests/test_history.py` 覆盖旧库迁移、中文短词、字面符号、带时区的半开时间范围、稳定位置续页、当前提问排除、Unicode 长文续读、同轮关联分页、读取边界、真实工具状态与故障反馈。使用实际 SDK 和原生流水线，进一步覆盖：

1. 文字与模拟语音均完成检索、原文读取、回复及工具结果保存。
2. 跨午夜的连续请求更新本地时间，模型历史没有积累时间提示。
3. 原读取来自文字或语音，新输入分别来自文字或语音，四种接管组合均取消旧调用；SQLite 旧操作结束后没有追加模型请求。
4. 同轮两个调用分别使用单独分块、同块多调用、交错参数，先完成的结果保存，未完成调用保存 `CANCELLED`。
5. 回读期间语音空闲期限暂停，尚未播报的新语音直接进入轮次，未调用重叠语音判意。

真实模型使用项目 `.env` 配置，读取独立临时数据库，种子记录未装入模型上下文，也没有读取用户日常数据库。三次请求均完成：

| 场景 | 实际行为 |
| --- | --- |
| 上周杭州出差的预算与碰头安排 | 模型按主题、时间检索，必要时改写查询，读取原文后回答“4186 元、周四 09:40、北门咖啡” |
| 月球养蜂计划不存在 | 模型换词检索，两次均为空，如实说明未找到并询问补充线索 |

自动化连续拼接长文核对了完整原文；真实模型末尾定位验证了按偏移展开，不将它视为模型逐页读完整篇的证明。
