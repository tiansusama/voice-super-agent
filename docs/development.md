# 开发运行

当前已接入 STS 语音链路、本地唤醒、组合键、结束语音、空闲超时、AEC、默认设备生命周期、语音/文字双向接管、故障恢复及失败文字重发。实现与自动化验证已完成，真实语音、外放、设备切换、交错输入和恢复演示待验收，结果见[语音链路记录](plan/V1.0.0/05-sts-voice.md)、[唤醒记录](verification/stage-06.md)、[音频设备记录](verification/stage-07.md)、[输入接管记录](verification/stage-08.md)及[恢复与重发记录](verification/stage-09.md)。页面启动和读取已保存记录无需模型凭据，发送文字需要配置 DeepSeek。

在已准备好的项目根目录启动桌面：

```powershell
uv run --locked voice-super-agent
```

`frontend/index.html` 是 Vite 源码入口，其中的 TypeScript/TSX 需要构建或由开发服务转换。浏览器通过 `file://` 直接打开它会白屏。完整应用由上述 Python 命令启动，宿主加载前端页面并提供后台桥接；开发服务模式见第 4 节。

## 1 环境

- Windows 11 x64。
- uv，项目使用 Python 3.12，通过 `.python-version` 与 `requires-python` 指定。
- Node.js 20.19 及以上的 20.x，或 22.12 及以上版本；本机准备时使用 Node.js 24。
- Microsoft Edge WebView2 Runtime 和 .NET Framework 4.6.2 及以上，供 pywebview 的 EdgeChromium 宿主使用。

Python 依赖由 uv 管理，前端使用 npm。以下命令均从项目根目录运行。

## 2 首次准备

```powershell
uv sync --locked
npm --prefix frontend ci
```

Pipecat 依赖声明来自官方 Git 仓库，使用 STS 对应提交 `de8998789d5690073ddd1dafcec7268839af8153`。第一次安装需要 Git 与网络，uv 会把源码放入自己的缓存并安装到本项目 `.venv`。所需版本由 `uv.lock` 记录，运行不使用旁边 STS 的源码或 `.venv`。

本地音频使用 Pipecat 原生输入输出处理器、PyAudio 设备回调和 `pywebrtc-audio==0.2.0` AEC3。Windows 默认端点与存活状态通过 `pycaw==20251023` 读取，所需 wheel 均由 uv 安装。Silero VAD 和 Smart Turn 使用锁定依赖自带的模型资源。

前端由 `frontend/package-lock.json` 记录确切依赖。本地唤醒需要额外下载 KWS 模型，准备步骤见 [资源说明](../resources/README.md)。

将 `.env.example` 复制为 `.env`，填写 `DEEPSEEK_API_KEY` 即可启用文字请求。已有 `.env` 时直接补充字段。模型默认 `deepseek-flash`，地址默认 `https://api.deepseek.com/v1`，可通过 `DEEPSEEK_MODEL` 和 `DEEPSEEK_BASE_URL` 设置，修改后重启应用生效。文字请求只使用 DeepSeek。语音凭据或本地模型准备失败时显示语音错误，文字和已保存历史继续可用。

语音联调还需要 `VOLCENGINE_API_KEY` 和 `ARK_API_KEY`，分别用于火山识别/合成与 System One。缺少语音配置时开发入口显示原因，文字对话继续使用自身配置。

启用语音前，从项目根目录执行 `./scripts/prepare-wake-model.ps1`。正常启动后程序使用默认麦克风进行本地检测，进入“待唤醒”；此时云端 ASR 未连接。说“你好小博”、按住 `Ctrl + \` 一秒，或点击主窗口“唤醒语音”，均可进入准备。云端 ASR 确认就绪后，经同一音频输出队列播放“叮”声，播放完成才开放指令输入。当前真实语音联调先使用耳机。

开发版先通过 `.env` 读取交互配置，修改后重启生效：

```dotenv
VOICE_WAKE_WORD=你好小博
VOICE_WAKE_HOTKEY=Ctrl+\
VOICE_IDLE_TIMEOUT_SECONDS=60
```

组合键支持 Ctrl、Alt、Shift、Win 与一个字母、数字、F1～F24、Space、Enter、Tab 或 `\` 的组合。额外修饰键按下时不触发；同次按住只唤醒一次，松开后继续对话；已激活时重复唤醒保持当前交互。超时接受大于 0 的整数秒，默认 60 秒。收音、识别、判意、生成、工具处理和播放期间暂停计时，再次等待用户时从完整时长开始。设置页与保存后的即时生效按阶段 14 接入。

主窗口“结束语音”可在准备、生成和播报期间使用；Agent 也可依据用户意图调用内部 `end_voice`，自行决定是否收尾，收尾回复和实际播放完成后回到待唤醒。空闲到期同样返回待唤醒。返回时关闭 ASR，恢复本地检测，当前上下文继续保留。待唤醒时 UI 文字只生成文字回复，语音保持待唤醒；活动语音期间可以直接发送文字接管，语音继续激活，回复形式跟随新输入。

文字接管会结束旧 ASR 连接，清理未提交的语音聚合和判意候选，再按原生顺序打断、提交旧回复及追加文字。已经显示的语音片段沿原有展示历史保存，已提交模型历史保留；旧连接及旧队列的转写继续携带原输入归属，后到的结果被排除。原生 worker、音频设备和 AEC 继续存续。

接管时用户还在说话，会沿用 VAD 等待该段发言结束，再接收后续新发言。新 ASR 连接在后台准备，文字回复可先开始；属于新输入的音频在连接准备期间仅作短时内存缓冲。普通接管不重复播放唤醒叮声。识别连接准备、旧发言尾段和回复处理期间暂停空闲计时，全部完成后重新等待。语音正在启动或结束的短暂切换期间，文字发送暂不可用。数据源、接入位置与验证结果见[跨输入接管记录](verification/stage-08.md)。

待唤醒时检测到 Windows 默认录音或播放端点变化，会关闭旧流、刷新 PortAudio 枚举并重建 AEC/KWS 音频入口；原生 worker、上下文和正在进行的文字回复保留。活动语音中旧设备仍可用时继续使用，返回待唤醒后切换，唤醒前也会检查当前默认设备。端点或音频流失效后停止语音并显示原因；点击主窗口、可见悬浮卡片或托盘的“恢复语音”打开当前默认设备，成功后回到待唤醒，由用户再次唤醒。恢复时若正在生成文字，会立即打断并提交已有片段，等待旧对象释放后重建语音；此前的问题和回答继续保留，恢复成功后等待新输入。恢复使用本次启动的有效配置，修改 `.env` 后仍需重启应用。

后台快照已提供独立的 `microphone_level` 和 `playback_level`（0～1），分别来自 AEC 后的收音和到达 DAC 时刻的播放数据，按最多 20 Hz 推送。收音球与播报音波的实际渲染按阶段 13 接入。音频格式、参考时序及实机验收安排见[音频设备验证记录](verification/stage-07.md)。

## 3 加载前端构建产物

```powershell
npm --prefix frontend run build
uv run --locked voice-super-agent
```

构建先进行 TypeScript 检查，再生成 `frontend/dist`。桌面通过 pywebview 的本地静态服务加载页面。没有构建产物时，启动命令会说明需要执行的构建命令。

页面就绪后订阅 `agent-runtime` 线程的状态，显示“文字对话已就绪”或配置缺失原因。输入消息后按 Enter 发送，Shift + Enter 换行；中文输入法选词时的 Enter 保留给输入法。回复期间可以发送新消息接管，已显示的旧回复文字保留，新回复结合原生提交的上下文生成。

页面重载后重新取得消息快照，后续推送按序号衔接。主窗口隐藏或最小化期间，后台继续生成。消息和原生模型上下文保存在本工作副本的 `.local/data/agent.sqlite3`，明确退出后重新启动会恢复当前展示范围及上下文，可以继续追问。

生成期间退出时，应用先取消当前处理，保存已展示文字与原生实际提交内容，再关闭窗口。未完成回复保留后台状态，重启后等待用户继续输入。原生上下文独立保存；界面展示文字按已有规则正常显示。

请求失败原因显示在对应助手消息旁。模型临时请求错误后可以继续提问；鉴权等永久模型错误会显示需要检查配置并重启的提示。ASR、System One、TTS 或音频失败会停止语音，模型可用时发送文字会在已有上下文上创建文字执行对象。TTS 失败保留已展示文字。

回答失败的文字用户消息旁提供“重新发送”：从原消息复制正文，追加为底部的新消息，生成文字回复；原消息、旧错误和旧回复片段保留，输入框草稿保留。语音消息由用户再次提问。应用和 SDK 均关闭自动请求重试。

主窗口显示具体原因与恢复结果；可见悬浮卡片保留当前语音问答并提供恢复入口，附和继续归属原问答。手动隐藏的悬浮组件保持隐藏，托盘提示语音或模型不可用，并按能力启用“恢复语音”。完整悬浮显示规则和最终视觉在阶段 12～13 复核。

关闭主窗口或点击“隐藏到托盘”后应用继续运行。最小化保留 Windows 的最小化状态。双击托盘图标或选择“显示主窗口”可找回主窗口；再次执行启动命令也会唤出同一个窗口。通过页面或托盘的“退出应用”结束应用和后台循环。

页脚显示“正在保存对话”或“对话已保存在本机”。保存失败时显示具体原因，并暂停接收新消息；退出时保存失败会保留并显示主窗口。处理磁盘、权限等原因后，再次点击“退出应用”会重新尝试最终保存，成功后退出。读取数据库失败时同样显示原因并暂停新消息，原数据库保留。

## 4 连接 Vite 开发服务

先在一个终端运行：

```powershell
npm --prefix frontend run dev
```

保持该终端运行，在另一个终端启动桌面：

```powershell
uv run --locked voice-super-agent --dev
```

开发服务固定监听 `http://127.0.0.1:5178`，仅在本机访问；端口被占用时 Vite 直接报错。`--dev` 在打开窗口前检查服务连接，未启动时给出原因和命令。修改 React 页面可通过 Vite 更新桌面内容。

明确退出桌面后，在运行 Vite 的终端按 `Ctrl+C` 结束开发服务。

## 5 桌面联调

加载构建产物并打开联调入口：

```powershell
uv run --locked voice-super-agent --desktop-check
```

也可以与 `--dev` 一起使用。主窗口会增加“桌面联调”区域：

- “开始后台活动”启动真实 asyncio 任务，每秒产生约 20 次计数状态；停止后保留当前计数。
- “预览悬浮宿主”隐藏主窗口，在工作区右下角显示圆角卡片和圆球。卡片支持内部滚动，圆球切换卡片展开与收起。
- 卡片的“×”只隐藏悬浮组件；托盘中的“显示收音窗”可找回已预览过的宿主。“打开主窗口”会收起悬浮组件并显示主窗口。

语音入口已放在普通主窗口。采集、AEC 和设备播放统一请求 16 kHz、16 bit、单声道，每个设备回调块为 10 ms；火山 TTS 仍返回 24 kHz，由原生输出端重采样为设备格式，叮声使用相同路径。ASR 分句定稿由原生用户轮次继续聚合；播报期间的附和记录在展示历史中，接管则保留旧回复片段并发起新轮次。

联调区域用于验证窗口、线程和推送。语音驱动的自动显示、收音音量环和单轮问答在对应阶段接入。普通启动时托盘的“显示收音窗”先保持不可用。

可以在后台活动持续运行时关闭主窗口、重复启动、最小化或重载页面，检查计数接续；完成后通过“退出应用”结束任务和窗口。当前计数属于内存联调状态，明确退出后归零。

## 6 数据与产物位置

| 位置 | 用途 | Git 管理 |
| --- | --- | --- |
| `.venv/` | 本项目 Python 环境 | 忽略 |
| `frontend/node_modules/` | 前端依赖 | 忽略 |
| `frontend/dist/` | 前端构建产物 | 忽略 |
| `.env` | 本地服务凭据 | 忽略；提交配置示例 |
| `.local/data/agent.sqlite3` | 展示历史、原生模型消息与当前工作范围 | 忽略 |
| `.local/logs/app.log` | 启动、订阅、窗口操作和退出日志 | 忽略 |
| `.local/webview/` | WebView2 本地存储 | 忽略 |
| `resources/models/` | 本地 KWS 模型与下载包 | 忽略；资源说明纳入仓库 |
| `uv.lock`、`frontend/package-lock.json` | 依赖解析结果 | 提交 |

当前开发数据位置位于各自工作副本内，换一个副本会创建自己的 `.local`。

首次打开数据库时应用自动执行已确认版本的初始化脚本 `src/voice_super_agent/memory/migrations/V1.0.0_001__init_conversation.sql`，无需手工执行 SQL。数据库工作由单独的串行 I/O 线程处理，流式片段按短批次合并；用户提交、原生上下文提交和正常退出会触发及时保存。结构、保存时机与恢复规则见 [架构说明](design/V1.0.0-architecture.md#71-sqlite-保存)。

## 7 检查命令与问题定位

```powershell
npm --prefix frontend run typecheck
uv run --locked pytest -q
uv run --locked voice-super-agent --help
uv run --locked python -c "import sys; import voice_super_agent; print(sys.executable); print(voice_super_agent.__file__)"
```

- 缺少前端产物：执行构建命令后重试。
- `--dev` 连接失败：先启动 Vite，检查终端输出与 5178 端口。
- 桌面引擎启动失败：核对 WebView2 Runtime、.NET 和终端异常；已启用的文件日志位于 `.local/logs/app.log`。
- 页面一直连接中：检查是否在 pywebview 桌面内打开；普通浏览器不提供 Python 桥接。查看桌面终端和日志中的页面订阅结果。
- 对话保存异常：查看界面与日志中的具体原因，检查数据库所在目录及磁盘状态；处理后再次点击“退出应用”保存并退出。
